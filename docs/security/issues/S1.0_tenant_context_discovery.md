# Issue S1.0: Tenant Context Infrastructure Discovery

**Status**: ✅ Resolved  
**Date Resolved**: 2026-06-19  
**Phase**: S1A (Infrastructure)

## Description

Physical tracing of tenant context (`organization_id`) from its origin through all execution paths: API requests, web views, Celery tasks, management commands, and tests. Answer 6 governance questions:

1. Where does organization_id originate?
2. How does it travel to views?
3. How does it reach Celery tasks?
4. How does it reach management commands?
5. How does it reach tests?
6. Is there a single source of truth?

## Resolution

See `docs/security/tenant_context_discovery.md` for complete infrastructure audit.

**Key Findings**:

### Origin: 4 Fragmented Sources
1. **JWT Claim** (embedded but UNUSED by middleware) — dead code
2. **User.organization FK** (fallback, not for superusers)
3. **X-Org-ID Header** (manual, required for superuser escalation)
4. **URL Slug** (web views only)

### Journey to Different Layers

| Layer | Path | Status |
|-------|------|--------|
| **API Request** | Middleware (X-Org-ID/User.org) → thread-local → TenantManager | ✓ Working |
| **Web View** | Middleware (URL slug) → thread-local → TenantManager | ✓ Working |
| **Celery Task** | Entry.organization_id → explicit filter in UseCase | ⚠️ Fragile |
| **Management Command** | Explicit set_current_organization() | ✓ Correct |
| **Tests** | Explicit organization= parameter | ⚠️ Manual |

### Exit Criteria (S1A)

| Criterion | Status | Details |
|-----------|--------|---------|
| **Single source of truth?** | ❌ | 4 sources, no consolidation |
| **Celery preserves tenant?** | ⚠️ | Works by accident; missing explicit context |
| **Commands are tenant-aware?** | ✅ | Explicit context management |
| **Tests simulate isolation?** | ❌ | Manual org= params; no TenantManager validation |

### Recommendations (S1 Implementation)

1. **Consolidate JWT Claim**: Extract org_id from token in middleware (currently ignored)
2. **Make Celery Explicit**: Wrap tasks with TenantContextManager before UseCase
3. **Implement Test Suite**: 17 tests validating automatic tenant filtering (S0.7 plan)
4. **Document Single Source**: Make organization_id flow explicit and traced
