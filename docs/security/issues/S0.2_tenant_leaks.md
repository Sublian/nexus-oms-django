# Issue S0.2: Tenant Leak Audit

**Status**: ✅ Resolved  
**Date Resolved**: 2026-06-19

## Description

Audit codebase for tenant isolation leaks. Search for:
- `.objects.all()` without organization filter
- `.all_objects` usage without explicit filtering
- Raw SQL queries (`raw()`, `cursor.execute()`)
- select_related/prefetch_related crossing tenant boundaries
- Celery tasks accessing data globally

## Resolution

See `docs/security/tenant_leak_audit.md` for complete audit.

**Critical Findings (4)**:
- `ProductViewSet.get_queryset()`: `Product.all_objects.all()` when org=None
- `OrderViewSet.get_queryset()`: `Order.all_objects.all()` when org=None
- `ReportViewSet.get_queryset()`: `SalesReport.all_objects.all()` when org=None
- `OrderReturnViewSet.get_queryset()`: `OrderReturn.all_objects.all()` when org=None

**High Risk (11)**:
- Dashboard service + Web views use explicit `.filter(organization=...)` mitigating risk

**Raw SQL**: 0 findings ✅

**Remediation**: S1 (close critical leaks via T1 API ViewSet fix)
