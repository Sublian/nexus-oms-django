# Issue S0.3: Superuser Governance Review

**Status**: ✅ Resolved  
**Date Resolved**: 2026-06-19

## Description

Review how superuser (`is_superuser=True`) privilege interacts with multi-tenant isolation. Identify:
- Escalation paths (how can superuser bypass org restrictions?)
- Governance gaps (lack of audit, rate limiting, MFA)
- Mitigation strategy (T6 controls)
- Database vs application enforcement

## Resolution

See `docs/security/superuser_governance.md` for complete analysis.

**Key Findings**:
- Superuser can access any org via X-Org-ID header
- No X-Org-ID requirement → returns `all_objects.all()` (leaks all data)
- No audit log of superuser access
- No RBAC enforcement in ViewSets (VIEWER can write)
- `CustomUser.organization` nullable (org-less superusers allowed)

**Governance Gaps (6)**:
- G1: No explicit superuser authorization model
- G2: No audit trail
- G3: No rate limiting
- G4: No opt-in workflow for org-less superusers
- G5: Role enforcement missing
- G6: No MFA (S2)

**Mitigation Controls (T6)**:
- T6.1: Require X-Org-ID for superuser (S1) — CRITICAL
- T6.2: Audit logging (S1) — HIGH
- T6.3: Role-based RBAC (S1) — HIGH
- T6.4-T6.6: MFA, key rotation, RLS (S2)
