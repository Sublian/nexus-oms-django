# Issue S0.5: Data Classification Sensitivity Mapping

**Status**: ✅ Resolved  
**Date Resolved**: 2026-06-19

## Description

Classify each model and critical fields by sensitivity tier:
- Public (no RLS needed)
- Internal (RLS recommended)
- Confidential (RLS required)
- Sensitive (RLS + encryption + masking required)

For each tier, define:
- What data? Examples?
- RLS requirement
- Masking strategy (for logs)
- Encryption requirement

## Resolution

See `docs/security/data_classification.md` for complete matrix.

**Classification Summary**:
- Public (2): Category, ExchangeRate
- Internal (8): Supplier, Warehouse, Stock, StockMovement, TaxConfiguration, CashReconciliation, CompanyInvoiceConfig, PurchaseOrder, PurchaseOrderItem
- Confidential (10): Client, Product, Order, OrderItem, OrderReturn, Payment, SalesReport, AccountingEntry, AccountingEntryLine, OrderWorkflowLog
- Sensitive (3): CustomUser, ExternalServiceConfig (credentials), ExternalRequestLog (audit logs)

**Masking Requirements**:
- PII fields: Email, phone, document_number, address (mask in logs)
- Financial: Amounts, transaction refs (mask/round in logs)
- Credentials: api_key, api_secret (never log, show only tail)

**Compliance Mapping**:
- GDPR: Client, Order, CustomUser, ExternalRequestLog
- SOC2: All confidential + sensitive models
- PCI-DSS: Payment, Payment-linked data
